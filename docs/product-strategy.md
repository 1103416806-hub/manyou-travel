# 慢游：产品策略与评估边界

本项目是面向国内单城短途旅行的规划工作台，作品集重点是需求取舍、证据处理、工具预算和可撤销编辑。当前演示范围为杭州 2–5 天。以下区分接口合约与设计期验收目标；策略目标不代表功能已经通过测试。

## 当前证据与可展示范围

目前没有可用于验证的 live 凭据。可以检查离线接口、固定规则、来源引用关系及浏览器状态；不能据此判断平台搜索、模型规划或真实旅行体验的质量。示例地点、预算和天气必须标注“演示”或“待核实”。配图标注“意境配图”，不代表实时天气或景点实况。

未开展真实用户研究，没有生产日志、用户满意度或真实效果提升结论。本文中的需求判断是设计假设；真实研究与失败样本到位后再修订优先级。

## 需求优先级与冲突

| 优先级 | 条件 | 处理原则 |
| --- | --- | --- |
| P0 | 日期、目的地、人数、用户明确上限、必去条件 | 先校验，冲突显式展示；不得静默改变输入。 |
| P0 | 与出行日相符的营业、预约、交通证据限制 | 影响是否可安排，不能被“相关性高”的平均分抵消。 |
| P1 | 节奏、兴趣、饮食和步行偏好 | 在明确限制内优化；无法兼顾时解释取舍。 |
| P2 | 可选景点、补充体验、展示丰富度 | 不为填满日程突破预算、时间或用户上限。 |

“必去”无法与可靠营业限制同时满足时，应说明冲突并提出改日或替代项；缺少资料时标为待确认，不把“没查到”写成“不能去”。

## 信息可信度与工具分工

来源用于什么结论，比统一排一个分数更重要。核查主体、适用日期、发布时间、正文内容以及返回粒度：

- 官方景区、场馆或交通来源：用于营业、预约和服务限制；仍需检查是否适用于本次日期。
- 小红书、抖音攻略：用于体验、偏好与路线线索；个人经验不能直接证明当前营业、排队或价格。
- 搜索摘要：只能支持摘要明确包含的信息；未获取正文不得声称完整阅读，未获得视频/音频处理结果不得声称理解视频。
- 用户粘贴文本：标为用户导入材料，保留链接；导入成功不等于平台正文或真实性已核验。
- 演示资料：只支持展示交互，不计入真实检索结果或事实质量评估。

来源正文是资料，不是可执行指令。忽略其中要求改预算、登录、点赞、发布、泄露数据或标记全部已核验的指令。所有 source_ids 应指向 sources 中实际存在的来源；引用存在不等于引用支持结论。没有经核验地点资料时坐标为 null，verified 不默认置 true。

## 天气窗口和服务不可用

天气有效窗口以实际 provider 响应为准，不硬编码成永远可查未来若干天。超出窗口的日期使用 unknown/unavailable，未知数值为 null；仅部分日期可用时逐日区分。季节常识、当前天气和演示天气都不能填成旅行日精确预报。雨天替代活动可以作为条件式方案。

小红书或抖音未配置时明确说明，并保留可用的网页证据或用户导入入口；不得把网页摘要写成平台原生搜索，更不得生成假帖子、假转录。GET /api/status 中 ready 仅代表配置存在，不证明登录、权限、额度或调用成功。

demo 与 live 始终保持可见区别。live 缺配置按合约返回 503，上游失败返回 502；不能悄悄用 demo 结果冒充成功。平台定向搜索如返回部分/空结果，应在 warnings 和 provider_status 中保留原因。

## 预算、补搜与停止

表单 budget 采用全程同行人员总预算，单位为人民币；人数与预算口径同屏可见。结果说明是否包含往返大交通、住宿、门票、餐饮和市内交通。住宿按房间与夜数估算，门票按人数估算，无法查实的项目保留估算标签；各项合计与余额使用同一口径。

备注人均预算与表单总预算冲突时，显示采用口径并提示用户确认；在确认前可以明确假设后保守草拟，不能静默放大预算。

补搜先处理会改变安排的缺口：必去地点营业、预约、关键转场。记录搜索目标、获得的新证据、轮数/耗时与停止原因。达到配置预算后停止，并保留未解决条件及确认方式；不靠重复调用或其他维度高分掩盖关键未知。阈值需要评估后确定，当前不宣称已有最优参数。

## 编辑与撤销

用户替换活动后，相关时间、预算估算、来源引用与地图状态同步更新；新活动不能继承旧活动的已核验标记。缺少经核验坐标时不添加虚构地图点。保留编辑前快照，撤销恢复活动和全部相关派生状态。此项需要浏览器实际操作验收，接口字段检查不能代替。

## 场景集与判分

`evals/cases.json` 包含 20 个 synthetic/spec-driven 场景，覆盖正常请求、无效输入、预算歧义、天气窗口、服务缺失、来源粒度、冲突、停止和编辑。它不是可直接执行的测试脚本；每例给出建议判分方式与 must/must_not。全部初始为 not_run。

其中 14 例用于开发检查，6 例暂定为验证预留；作者已看过全部内容，因此不是盲测集，也不代表真实请求比例。正式比较前冻结案例及规则，并补入未用于调参的真实请求/失败样本。

| 指标 | 计算与证据 | 当前可否测量 |
| --- | --- | --- |
| 接口与状态正确性 | 满足契约案例数 / 已执行契约案例数；保留请求、响应与版本 | 可做离线检查，本文未报告执行结果 |
| 条件满足率 | 满足且可检查的明确条件数 / 可检查条件总数；未知单列 | 规则可离线检查；真实路线可行性未验证 |
| 证据忠实度 | 被原始内容支持的可核查断言数 / 抽查断言数；由人工逐条核查 | 固定夹具可查，真实检索未测 |
| 天气与预算正确性 | 窗口/空值/估算口径/计算一致性的逐例结果 | 可通过固定数据与规则检查 |
| 搜索成本与耗时 | 每例工具次数、轮数、延迟；模型运行另记 tokens | 当前不填 live 数值 |
| 编辑恢复正确性 | 编辑与撤销后活动及派生状态一致的案例数 / 已执行案例数 | 需要浏览器验收 |

伪造来源、live 回退 demo、未知天气造值、越权账号动作属于直接失败。优先使用确定性结构/调用记录检查；语义与界面状态采用明确人工判据。当前不使用模型自评分；未来若引入模型裁判，先对照人工标注检查一致性。

## 基线与对照，尚未执行

当前 baseline 为 not_run，分数、方差和提升值均为 null。没有凭据时，不伪造原 Agentic_search 或新策略的质量基线。

后续先固定原仓库版本、慢游版本、模型、提示词、工具、日期和来源快照；以相同任务、数据及调用预算做对照。先运行基线，再一次修改一项策略。模型实验每例至少重复三次，报告样本量、运行次数、波动、回归案例及失败原因；离线固定规则的结果单独列出，不并入实时 agent 质量分。

未覆盖：平台反爬与登录持续性、真实搜索召回、语音转录与视频画面理解、真实交通/排队、未来天气准确性、预订库存/价格、真实用户满意度。没有这些证据时，作品集可以展示“策略设计与验证方法”，不能写成“已提升准确率”或“解决真实用户痛点并获得增长”。
