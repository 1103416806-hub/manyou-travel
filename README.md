# 慢游 MANYOU

把攻略资料、天气与旅行偏好整理成可编辑行程的旅行规划助手。第一版面向 AI 策略产品经理作品集，重点展示信息来源、条件约束、失败处理和用户调整的完整体验。

这是基于 Agentic_search 独立衍生的旅行产品项目。上游检索框架保留在 `src/agentic_search/`；旅行服务在 `manyou/`，界面在 `web/`。

## 第一版

- 杭州 2–5 天示例，按人数、日期和节奏生成每日安排。
- 在可拖动、缩放的地图上查看每日地点；点击标记查看地点信息、引用标题和原文，行程列表同步高亮。
- 带方向箭头的连线表示游览顺序；调整活动顺序、删除和撤销后，地图同步变化。
- 杭州示例的午餐以金色编号和虚线圈展示建议用餐区域，纳入当天的顺序箭头；点击可查看选区理由与位置参考来源。
- 在本机保存旅行与收藏资料，导出完整 Markdown 或打印当天行程。
- 真实天气查询，社交平台资料搜索和导入入口，明确显示连接情况与错误。
- 配置模型和检索服务后，可尝试实时生成；调用失败不会冒充真实结果返回示例。

**初次打开是杭州示例。天气、费用、交通和攻略资料均非实时信息。** 地图底图使用 OpenStreetMap，示例点位采用可追溯的地点代表点，入口仍需确认。杭州示例的午餐区域依据 OSM 参考点人工选择，虚线圈表示建议寻找餐馆的范围，不代表具体商家、实际餐饮覆盖或已核验营业。其余没有有效坐标的地点仍显示“待定位”，不生成虚构位置。箭头只表示顺序，不是导航。费用不含往返大交通；未接入实时路程计算、酒店机票库存或自动视频转写。

地图只按当前视口在线加载。若底图无法加载，页面会显示重试入口，地点资料仍可查看。已有杭州示例会修正旧演示坐标，保留日期、活动排序和删除操作。

第二天的午餐区域靠近博物馆，界面只移动屏幕上的编号标签，并以细线连接回真实区域中心；地理坐标保持不变。五个用餐区域的位置出处与手动选区说明见 `UPSTREAM.md`。

## 本地运行

需要 Python 3.11+ 与 Node.js 20.19+ / 22.12+。

```powershell
git clone https://github.com/1103416806-hub/manyou-travel.git
cd manyou-travel
python -m pip install -r requirements-travel.txt
cd web
npm install
npm run build
cd ..
python serve.py --port 8766
```

浏览器打开 http://127.0.0.1:8766 。构建后由 Python 同时提供网页和接口。也可运行 `start-travel.ps1` 启动已安装好依赖的项目。

开发界面时，先启动 Python 服务，再在 `web/` 运行 `npm run dev -- --host 127.0.0.1 --port 5275`。

## 数据连接

复制 `.env.travel.example` 为 `.env.travel`，仅在自己电脑配置密钥；配置文件不进入 Git。具体变量见该文件。

| 能力 | 第一版边界 |
| --- | --- |
| 杭州示例 | 无密钥可用；人工编排并明确标注 |
| Open-Meteo 天气 | 需要联网；超出预报窗口时返回未知 |
| 小红书 | 需要运行并登录独立的小红书 MCP 服务；只读搜索和详情 |
| 抖音关键词检索 | 需要开放平台授权与搜索权限；摘要不等于视频内容理解 |
| 网页检索 | 需要支持的搜索服务密钥 |
| 实时规划 | 需要模型配置及可用资料；事实、预约和交通仍需核实 |

收藏和旅行保存在本机浏览器，不跨设备同步。配置状态只说明已填写，不能证明平台登录、权限或额度有效。

## 作品集与验证

- `docs/research.md`：竞品调研与取舍。
- `docs/product-strategy.md`：目标、策略与评估方案。
- `docs/qa.md`：实际运行与界面检查记录。
- `docs/map-qa.md`：交互地图、方向箭头与用餐区域的检查记录。
- `evals/cases.json`：合成验收场景，未运行不记为通过。
- `UPSTREAM.md`：上游版本、参考与许可。

离线回归：`python -m unittest discover -s evals -p 'test_*.py' -v`。结构测试通过不代表攻略准确、用户满意或真实搜索质量已验证。
